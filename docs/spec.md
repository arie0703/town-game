# TOWNゲーム 要件定義書（spec）

---

## 1. 概要

ブラウザで遊べるTOWNゲーム（バーチャル世界での生活シミュレーション）を作る。
プレイヤーは町の住民として登録し、仕事でお金を稼ぎ、学校・ジムで能力を鍛え、アイテムを集め、他の住民と戦ったり恋人・配偶者になったりする。

### 1.1 方針

- 実装はシンプル・最小限とする。実装が重い要件は「後回し（Phase 2 以降）」として本書に残し、後から追加する。
- 要件には優先度を付ける。
  - **MVP**: 最初のリリースに必須
  - **P2**: MVP後に追加する候補
  - **P3**: 余裕があれば検討する

---

## 2. 技術構成

- フロントエンド: HTML / CSS / TypeScript の SPA（フレームワークなし、ビルドは Vite、hash ルーティング）
- バックエンド: TypeScript（Node.js + Hono）
- DB:
  - ローカル開発: SQLite（ファイル1つで完結させる）
  - 公開サーバー: Supabase の PostgreSQL
- DBアクセス: Kysely（SQLite / PostgreSQL の両方に対応するクエリビルダー）
  - MVP は SQLite のみ対応。PostgreSQL 対応（環境変数での接続先切り替え）はデプロイ時（P2）に追加する
  - 後で PostgreSQL に移せるよう、方言依存の機能（SQLite 固有の挙動等）は使わない
  - マイグレーションの仕組みは作らず、起動時に `CREATE TABLE IF NOT EXISTS` でテーブルを作成する
- マスタデータ（職業・アイテム・メニュー・マップ）: TypeScript の定数ファイルで持ち、DB には入れない
- 通信: JSON REST API
- 認証: Hono の署名付き Cookie にユーザー ID を保存する（セッションテーブルは作らない）。パスワードはハッシュ化（bcrypt 等）して保存する
  - Supabase Auth は使わない（ローカル SQLite 環境と認証方式を揃えるため）。P2 以降で移行を検討してもよい

> 補足: ログイン・他ユーザーとのストリートファイト・恋人/配偶者など「他ユーザーとの関わり」があるため、localStorage だけでは成立しない。最小構成としてサーバー + DB を採用する。
> ゲームロジック（勝敗判定・給料計算など）は不正防止のため必ずサーバー側で計算する。

### 2.1 環境

- **ローカル開発**（MVP）: `npm run dev` でフロント（Vite）・サーバー（Hono）を起動。DB は SQLite
- **公開サーバー**（P2）: AWS Fargate（ECS）でサーバーを動かす想定 + Supabase PostgreSQL
  - アプリはコンテナ（Dockerfile）で動かす。Hono が API とビルド済み SPA の静的配信を両方担う
  - 接続情報（DB URL・セッション秘密鍵）は環境変数で渡し、リポジトリにコミットしない

## 3. 用語

- **住民（ユーザー）**: ゲームに登録したプレイヤー
- **能力**: 頭脳・身体・その他の各パラメータ（鍛えると上がる、恒久的な値）
- **パワー**: 行動に消費する値（身体パワー・頭脳パワー）。休息・アイテム・食堂メニューで回復する
- **コンディション**: 体調。行動結果（給料・勝率・トレーニング効果）に影響する

## 4. 機能要件

### 4.1 アカウント（MVP）

- 住民登録ができる（ユーザー名・パスワード）
  - ユーザー名は一意。文字数制限（例: 2〜12文字）
  - パスワードは8文字以上
- 登録時に初期パラメータを付与する
  - 能力: 全項目 20
  - 身長: 150〜200cm のランダム（整数）
  - 体重: 45.0〜90.0kg のランダム（0.1kg 単位）
  - 職業: 無職
  - 所持金: 10,000円（仮）
  - 身体パワー・頭脳パワー: 最大値
  - コンディション: 100、満腹度: 50（仮）
  - 恋人・配偶者: なし
- ログイン / ログアウトができる
- ログイン状態はセッションで保持する
- （P2）パスワード変更
- （P3）退会（データ削除）

### 4.2 能力（MVP）

各能力は 0 以上の整数。**上限なし**（後で上限を追加する可能性あり → 上限値を1箇所の定数で管理できる作りにしておく）。

- **頭脳**: 国語 / 数学 / 理科 / 社会 / 語学 / 音楽 / 美術
- **身体**: ルックス / 体力 / 健康 / スピード / パワー / 腕力 / 脚力
- **その他**: LOVE / 面白さ

派生値:

- **頭脳合計**: 頭脳カテゴリの合計（就職条件・頭脳パワー最大値に使用）
- **身体合計**: 身体カテゴリの合計（就職条件・身体パワー最大値・ストリートファイトに使用）

### 4.3 ステータス（MVP）

- **持ち金**: 現金
- **預金**: 銀行に預けているお金
- **総資産**: 持ち金 + 預金 + 所有土地の評価額
- **職業**: 現在の職業（初期値: 無職）
- **身体パワー**: 現在値 / 最大値。仕事・ジム・ストリートファイトで消費。最大値は身体合計から算出
- **頭脳パワー**: 現在値 / 最大値。仕事・学校で消費。最大値は頭脳合計から算出
- **コンディション**: 0〜100。仕事・敗北・満腹度の低下で低下、休息・アイテム・食堂メニューで回復（食事によっては低下するものもある）
- **身長**（cm）: 闇市場の薬で増減する。120〜220cm
- **体重**（kg、0.1kg 単位）: 食事で増加、トレーニング・仕事で減少。30〜200kg
- **BMI**: 体重(kg) ÷ 身長(m)² で自動計算（表示のみ・保存しない）
- **満腹度**: 0〜100（100 = 満腹MAX）。仕事・ジム・ストリートファイト・休息などの行動で減少、食事（食事アイテム・食堂）で回復
- **恋人**: 恋人のユーザー（0〜1人）
- **配偶者**: 配偶者のユーザー（0〜1人）

コンディションの補正（例）:

- 満腹度が一定以下（例: 20未満）のとき、行動するたびにコンディションが低下する
- BMI が標準範囲（18.5〜25）から外れると、アイテム・食堂メニューによるコンディション回復量が半分になる（休息・コンディション低下には適用しない）

### 4.4 マップ（MVP）

- 15×15 のマス目で町を表示する
- 各マスは「施設」「空き地」「道（何もない）」のいずれか
- 施設のマスをクリックすると施設画面に入る（キャラクターの移動・移動時間は設けない）
- ホームの地図では、施設にカーソルを合わせる（またはキーボードでフォーカスする）と、「町の地図」の見出しの横に施設名と説明を小さく表示する
- 施設配置は固定（マスタデータで定義）
- 各マスはアイコンで表示する
  - 施設・空き地・購入済みの土地は 32×32 のドット絵アイコン（コードで定義）
  - 購入済みの土地には家を表示し、屋根の色で所有者を区別する（自分の土地: 赤、他の住民の土地: 橙）
  - `assets/icons/` に「アイコン名.拡張子」で画像を置くと、ドット絵の代わりにその画像を使う（手順は [icon-assets.md](icon-assets.md)）。外部素材を使う場合は配布元の利用規約を確認する
- 1マスは 32px 固定（アイコンを等倍で表示するため）
- 各施設には店主がいて、施設画面に店主のアイコン（32×32 のドット絵を2倍表示）とセリフ（吹き出し）を表示する。セリフは施設ごとに複数用意し、表示のたびにランダムで選ぶ

施設一覧:

- **お店**（MVP）: アイテム購入
- **職業安定所**（MVP）: 職業の確認・転職
- **学校**（MVP）: 頭脳能力を上げる
- **トレーニングジム**（MVP）: 身体能力を上げる
- **ギャンブル施設**（MVP）: お金を賭ける
- **不動産屋**（MVP）: 空き地の購入
- **空き地**（MVP）: 不動産屋で購入可能な土地。購入済みなら所有者名を表示
- **食堂**（MVP）: その場で食事をする
- **居酒屋**（MVP）: お酒と料理を注文できる
- **役場**（MVP・追加提案）: 住民一覧（総資産ランキング順）の閲覧
- **病院**（P2）: お金を払ってコンディションを全回復
- **銀行**（MVP）: 持ち金の預け入れ・引き出し（送金は P2）
- **闇市場**（MVP）: 体重・身長を大きく変える薬や、能力が大きく上がる高価な品を売る路地裏の露店（マップ右下の角）

### 4.5 アクション: 仕事（MVP）

- 職業に就いた状態で「仕事」をすると給料が得られる
- 職業ごとに以下を定義する（マスタデータ）
  - 基本給
  - 就職条件（例: 頭脳合計 ≥ N、身体合計 ≥ N、特定能力 ≥ N、BMI の範囲、体重 ≥ N kg）
  - 消費パワー（身体パワー / 頭脳パワーのどちらを何ポイント）
  - コンディション低下量
  - 仕事で上がる能力（例: プログラマーは数学 +1）
  - 1回働いたときの体重の増減（kg。身体を使う仕事ほど減る。接待の多い上位職などは増える）
- 給料 = 基本給 × コンディション補正（例: コンディション50未満で減額）
- パワーが足りない場合は仕事できない
- 職業の例:
  - 無職（仕事不可）
  - アルバイト（条件なし・低賃金）
  - 教師（国語・社会が一定以上）
  - プログラマー（数学が一定以上）
  - フィットネストレーナー（身体合計が一定以上）
  - モデル（ルックスが一定以上、BMIが範囲内）
  - 芸人（面白さが一定以上）
  - 前相撲（体重 80kg 以上・パワーが一定以上）
  - 道場生（身体合計・腕力が一定以上）
  - 町のカレー屋（理科・語学が一定以上）
  - バー見習い（語学・LOVE が一定以上）
- 1回働いたときの体重の例: フィットネストレーナー -0.8kg、アルバイト・モデル -0.5kg、教師・芸人 -0.3kg、プログラマー -0.1kg、前相撲 +0.4kg、町のカレー屋 +0.3kg
- **職業レベル**: 1回働くとその職業の経験値が 1 増える。経験値 0 / 10 / 30 / 60 / 100 で Lv1〜5。経験値は職業ごとに保存し、転職しても残る
- **上位職（昇進）**: 職業には系統があり、上位職ほど給料・能力上昇・体重の変化が大きい
  - 系統: アルバイト → バイトリーダー → 店長 / 教師 → 教頭 → 校長 / プログラマー → シニアエンジニア → CTO / フィットネストレーナー → パーソナルトレーナー → ジムオーナー / モデル → 人気モデル → トップモデル / 芸人 → 売れっ子芸人 → 大御所 / 前相撲 → 幕下 → 横綱 / 道場生 → 総合格闘家 → チャンピオン / 町のカレー屋 → 本格カレー店主 → 行列のカレー職人 / バー見習い → バーテンダー → マスターバーテンダー
  - 昇進条件: 能力値（通常の就職条件）に加えて、昇進元の職業に就いていること、昇進元の職業レベル、総資産（一部の職業）
  - 昇進は職業安定所で手動で行う（「昇進する」ボタン）
- （P2）職業レベルに応じた昇給

### 4.6 アクション: 休息（MVP）

- ホーム画面から「休息」を実行すると、身体パワー・頭脳パワーが 50、コンディションが 30 回復する
- 休息には BMI 補正・満腹度ペナルティをかけない（基本の回復手段として、常に一定量回復する）
- 無料で実行できる（お金がなくても詰まないようにするため）
- 休息すると満腹度が 5 減る（休息を繰り返すには食事が必要＝お金がかかる、という循環を作る）
- 満腹度が 0 のときは休息できない
- 回復量は定数で管理し、調整できるようにする

### 4.7 アクション: 職業安定所（MVP）

- 職業一覧と就職条件・給料を表示する
- 条件を満たす職業に転職できる
- 退職（無職に戻る）ができる

### 4.8 アクション: ストリートファイト（MVP）

- 「戦う」を押すと、自分以外の住民からランダムに対戦相手が選ばれる（相手はオンラインでなくてもよい。相手の操作は不要）
  - 相手を指名することはできない
- 身体パワーを消費する
- 勝率は身体能力（身体合計 + パワー・スピード等の重み付け）の比で決める
  - 例: 勝率 = 自分の戦闘力 ÷ (自分の戦闘力 + 相手の戦闘力)、コンディションで補正
  - 下限・上限を設ける（例: 5%〜95%）＝弱くても勝てる可能性を残す
- 勝敗の影響を受けるのは **挑戦した側のみ**
  - 勝利: 町から賞金を得る（金額は仮: 相手の戦闘力に応じて増える）
  - 敗北: **持ち金が半分になる**（端数切り捨て、失ったお金は消滅）。加えてコンディションが大きく低下する
- 挑戦された側には一切影響しない（お金・コンディション・パワーなどすべて変化なし）
- 戦闘結果は挑戦した側の出来事ログにのみ記録する（挑戦された側には履歴も残らない）
- （P2）勝敗数・ファイトランキング

### 4.9 アクション: アイテム（MVP）

- お店でアイテムを購入できる（所持金から差し引く）
- 所持アイテムを一覧表示し、使用できる
- アイテム種別:
  - **食事アイテム**: 満腹度を回復、体重が増える。**満腹度がMAXのときは使用不可**
  - **能力アップアイテム**: 特定能力を上げる（例: 参考書 → 数学 +5）
  - **回復アイテム**: コンディション・パワーを回復（例: 栄養ドリンク）
- アイテムの種類（食事・能力アップ・回復）はお店での分類の目安。効果（身体パワー・頭脳パワー・コンディションの回復、体重の増減、能力上昇）はどの種類にも付けられる（例: プロテイン → 身体パワー +30・パワー +5）
- ただし満腹度の回復は食事のみ
- コンディションは食事でも変化する。下がるアイテムもある（例: 激辛カップ麺 → コンディション -10）
- すべてのアイテムに能力上昇の効果がある（例: ステーキ → パワー +2・腕力 +1、入浴剤 → ルックス +1・健康 +1）
- アイテムの効果説明はマスタの値から自動生成する
- 使用すると所持数が減る（消耗品）
- （P2）アイテム売却（リサイクルショップ）
- （P2）他ユーザーへのアイテムプレゼント
- （P3）コレクション用アイテム（使用不可・図鑑表示）

### 4.10 アクション: 学校（MVP）

- 授業を選んで受講する。授業ごとに消費する頭脳パワー・授業料・上がる能力（複数可）を定義する（マスタデータ）
  - 例: 理科実験 → 理科 +3・数学 +1、英会話 → 語学 +3・面白さ +1、調理実習 → 健康 +2・美術 +1・コンディション +5
- 上昇量はコンディションで補正する（80以上: そのまま、50以上: 0.6倍、それ未満: 0.3倍。最低 +1）

### 4.11 アクション: トレーニングジム（MVP）

- 種目を選んでトレーニングする。種目ごとに消費する身体パワー・利用料・上がる能力（複数可）・体重の変化を定義する（マスタデータ）
  - 例: ベンチプレス → パワー +2・腕力 +2、ランニング → 脚力 +2・体力 +2・体重 -1.0kg、ヨガ → 健康 +2・ルックス +1・コンディション +5
- 上昇量の補正は学校と同じ。満腹度が減る

### 4.12 アクション: 食堂（MVP）

- メニュー（マスタデータ）から選んで、その場で食事をする（お金を払う）
- 満腹度が回復し、体重が増える（メニューごとに回復量・増加量・価格を定義）
- すべてのメニューに能力上昇の効果がある（例: カツ丼 → パワー +1・腕力 +1）。身体パワー・頭脳パワーが回復するメニューもある
- メニューによってコンディションが上がる・変わらない・下がる（例: ステーキ定食 +15、カツ丼 ±0、ギガ盛りラーメン -5）
- **満腹度がMAXのときは食事できない**
- お店の食事アイテムとの違い: 食堂は持ち歩けない代わりに、同じ回復量なら食事アイテムより安い
- **炊き出し**: 持ち金が **ちょうど 0円** のときだけ、無料の食事（おにぎり1個）をもらえる
  - 満腹度が少し回復する（回復量は通常メニューより少ない。仮: +30）
  - 炊き出しおじさんのアイコンとセリフを表示する。小銭が残っていて利用できないときは、断りのセリフを出す
  - 能力上昇・パワー回復などの効果はない（無料で何度でも利用できるため、効果を付けると能力を上げ放題になる）
  - 満腹度が 0 で休息もできず、お金もない状態で詰まないための救済措置
  - 1円でも持っていると利用できない（あえて厳しくしている）。小銭が残って何も買えないときは「丁半で最後の小銭を賭けて、勝てば食堂、負ければ炊き出し」という一か八かの選択をさせる
  - 銀行に預金がある場合は利用できない（全額を預けて持ち金を 0円 にし、無料で食べ続けることを防ぐ）
  - 持ち金が最安メニュー未満かつ 1円以上のとき、食堂画面に「炊き出しは一文無しの方限定です」と表示し、ギャンブル施設へ誘導する
  - 炊き出しを利用すると出来事ログに「炊き出しの列に並んだ」と記録し、利用回数を累計する

### 4.12.1 アクション: 居酒屋（MVP）

- お酒と料理を注文できる（食堂と同じくその場で飲食する）
- **お酒**: コンディションが下がり、体重が増える。代わりに面白さ・LOVE などが上がる（酔うと口が軽くなる）
  - お酒は別腹: 満腹度が MAX でも飲める。満腹度は回復しない
- **料理**: 満腹度が回復する（例: 焼き鳥盛り合わせ、〆のラーメン）。満腹度が MAX のときは食べられない

### 4.12.2 アクション: 銀行（MVP）

- 持ち金を預ける・預金を引き出すことができる（金額を指定、または全額）
- 預金はストリートファイトで負けても減らない（負けて半分になるのは持ち金のみ）
- 預金は総資産に含める
- 金利はつけない
- （P2）他の住民への送金

### 4.12.3 アクション: 闇市場（MVP）

### 4.17.1 ランダムイベント（MVP 後に実装）

- 対象の行動をしたとき、一定の確率（1回あたり 8%、config で調整）でランダムイベントが起きる。1回の行動で起きるイベントは最大1つ
- 対象の行動: 仕事・休息・ジム・学校・アイテム使用・食堂・居酒屋・闇市場での購入・ストリートファイト・丁半
  - 対象外: 転職・退職・お店での購入・銀行・炊き出し・不動産・恋愛
- イベントは「共通（対象のどの行動でも起きる）」と「特定の行動のみ」に分かれる。発生したときは、条件を満たす候補から重みに応じて1つ選ぶ
- 良い出来事と悪い出来事をおおむね半々にする。悪い出来事の多くは持ち金に対する割合で失うため、持ち金が多いほど痛い（預金は減らない）
- イベントの例
  - 共通: 道で100円を拾った / 財布を落とした（持ち金の 20%。持ち金 1,000円以上） / ひったくりに遭った（持ち金の 50%。持ち金 10,000円以上、低確率） / 野良猫になつかれた / 風邪をひいた / 宝くじが当たった（+30,000円、ごく低確率）
  - 仕事: 大きなミスをして給料がパーになった / ヘッドハンティングされた（経験値 +3）
  - 職業特有（仕事をしたとき、その系統の職業に就いている場合のみ。一部は特定の職業のみ。共通・仕事全般のイベントより起きやすい）
    - アルバイト系統: 常連さんに名前を覚えられた（給料 +30%） / レジのお金が合わず自腹を切った（-1,000円） / バイトが一斉に辞めた（店長のみ）
    - 教師系統: 教え子から感謝の手紙が届いた / 保護者からクレームが来た / 学校が表彰された（+10,000円。校長のみ）
    - プログラマー系統: 書いたツールがバズった（給料 +100%） / 本番環境を落として給料がパーになった / 徹夜でデバッグした
    - フィットネストレーナー系統: お客さんが劇的に痩せて口コミが広がった（給料 +50%、経験値 +1） / お手本を見せていて腰を痛めた
    - モデル系統: 雑誌の表紙に抜擢された（給料 +100%） / 撮影前にむくんでいて給料が半分になった / ゴシップ記事が出た
    - 芸人系統: ネタが大ウケした（給料 +100%） / 盛大にスベって給料がパーになった / 一発屋としてテレビに出演した（+5,000円。芸人のみ）
    - 相撲系統: 金星を挙げて懸賞金を得た（+5,000円） / 土俵際で足をくじいた / ちゃんこを食べすぎた（体重 +1.0kg）
    - 総合格闘技系統: KO勝ちしてファイトマネーを得た（給料 +100%） / 計量に失敗して罰金を払った（-3,000円） / 顔面に一発もらった
    - カレー系統: グルメサイトで高評価がついた（給料 +50%、経験値 +1） / まかないのカレーがうまくできた / スパイスの配合を間違えて給料が半分になった
    - バーテンダー系統: 常連客の恋愛相談に乗ってチップをもらった（+2,000円） / 高級ボトルを割って弁償した（-5,000円） / 客に付き合って飲みすぎた
  - 休息: ぐっすり眠れた / 悪夢を見た
  - ジム: スカウトされた（ルックス +2） / 筋肉を痛めた
  - 学校: 先生に褒められた（頭脳パワー +10、その授業で上がる能力 +1） / 居眠りして怒られた
  - 食堂: 大盛りサービス / 食べすぎてお腹を壊した
  - 居酒屋: 隣の席の人と意気投合した（LOVE +2） / 酔っぱらって転んだ / まわりの客におごらされた（-2,000円）
  - 闇市場: 偽物をつかまされ、買った品が消えた / おまけで同じ品をもう1個もらった
  - ストリートファイト: 通りすがりの師匠に技を教わった（腕力 +2） / 警察に止められて罰金を払った（-5,000円）
  - 丁半: イカサマを見抜いて掛け金を取り戻した（負けたときのみ）
- 効果: お金・満腹度・身体パワー・頭脳パワー・コンディション・体重・能力・今の職業の経験値・アイテムの個数の増減。値は 0 未満・上限超えにならないよう丸める（BMI 補正はかけない）
- イベントは行動の結果を反映した後の状態に対して抽選し、行動と同じトランザクションで反映する
- 結果のメッセージの下に「★ 出来事（効果）」を別の行で表示する（良い出来事は緑、悪い出来事は赤）。出来事ログには行動のメッセージに続けて記録する
- イベントの内容・重み・条件はマスタ（`src/shared/master/random-events.ts`）で定義する

## 5. 非機能要件

### 5.1 セキュリティ（MVP）

- パスワードはハッシュ化して保存する（平文保存禁止）
- 認証Cookieは署名付きとし、HttpOnly / SameSite=Lax を付与する
- 状態を変更する API は POST で受け、CSRF 対策を行う（Hono の `csrf` ミドルウェア）
- ゲームの計算（給料・勝敗・ギャンブル結果）はすべてサーバー側で行い、クライアントの値を信用しない
- ユーザー入力（名前・掲示板等）は出力時にエスケープする（XSS対策）
- ログイン試行回数の制限（P2）

### 5.2 整合性（MVP）

- お金・アイテムの増減はトランザクション内で行う（二重送信で二重に給料が入らないようにする）

### 5.3 UI / 動作環境（MVP）

- PC ブラウザ（Chrome / Edge / Firefox / Safari の最新版）で動作する
- スマホ対応は MVP では行わない（P2）
- 画面はシンプルなレトロ風デザイン（テーブル・枠線中心）で可
- マップの1マスは 32px 固定（マップ全体で約 500px 幅）

### 5.4 開発・運用

- （MVP）ローカルで `npm run dev` 一発で起動できる
- （MVP）テストコードは実装しない（動作確認は手動）
- （MVP）Lint / Formatter は導入しない（`tsc` の型チェックのみ）
- （MVP）1パッケージ構成とする（npm workspaces は使わない）
- （MVP）数値（給料・価格・回復量・初期値など）はマスタデータ / 定数ファイルにまとめ、ロジックを触らずに調整できる
- （MVP）マイグレーションの仕組みは持たない。ローカルで DB の列を変更するときは、データを残すため手動で `ALTER TABLE` を実行する（例: `hunger` → `fullness`、`weight` → `weight_g`）
- （P2）PostgreSQL 対応（環境変数 `DATABASE_URL` で接続先を切り替え）
- （P2）本番運用開始前に、DB 構造変更の扱い（マイグレーションの仕組みを入れるか）を決める
- （P2）公開サーバー（AWS Fargate 想定）へのデプロイ（Supabase PostgreSQL に接続）
- （P2）Supabase 側のバックアップ設定、本番用 Cookie 署名鍵の管理

## 6. データモデル（概略）

MVP で必要な主なテーブル:

- `users`: id, name, password_hash, money, deposit, soup_kitchen_count, job_id, body_power, brain_power, condition, height, weight_g, fullness, lover_id, spouse_id, created_at
- `abilities`: user_id, 各能力値
- `user_items`: user_id, item_id, quantity
- `user_job_exp`: user_id, job_id, exp（職業ごとの経験値）
- `lands`: cell_id, owner_id, purchased_price
- `relationship_requests`: id, from_id, to_id, type(交際/プロポーズ), status
- `events`: id, user_id, message, created_at（出来事ログ。ストリートファイトの結果もここに記録する）

マスタデータ（DB に入れず、TypeScript の定数ファイルで持つ）:

- 職業: id, name, base_salary, requirements, promotion（昇進元・レベル・総資産）, power_type, power_cost, condition_cost, fullness_cost, weight_change, ability_gain
- アイテム: id, name, price, shop（お店 / 闇市場）, effect（身長の増減を含む。type・満腹度〔食事のみ〕・パワー/コンディション回復・体重・能力上昇 gain）
- メニュー: id, name, price, shop（食堂 / 居酒屋）, drink, effect（満腹度・パワー回復・体重・能力上昇 gain）
- ジムの種目・学校の授業: id, name, facility, power_cost, fee, fullness_cost, weight, condition, gain
- 店主: 施設ごとの名前・セリフ
- マップ: 15×15 の各マスの type（施設 / 空き地 / 道）, facility_id, land_price

## 8. 未決事項（要確認）

### 8.1 決定済み

- ローカルは SQLite、公開時は Supabase PostgreSQL
- 初期値は能力 ALL 20、身長 150〜200cm / 体重 45〜90kg のランダム、職業は無職
- ギャンブルは丁半のみ
- ストリートファイトは挑戦した側のみ勝敗の影響を受ける。敗北時は持ち金が半分、挑戦された側は影響なし
- 能力値の上限なし（後で追加する可能性あり）
- バックエンドは Hono
- テストコードは実装しない
- フロントエンドは SPA（hash ルーティング）、1パッケージ構成
- MVP は SQLite のみ対応、PostgreSQL 対応はデプロイ時
- ストリートファイトの相手はランダムのみ。挑戦された側の履歴は残さない
- 不動産は購入のみ
- 住民一覧は総資産ランキングを兼ねる（プロフィール画面なし）
- 総資産は持ち金 + 土地
- スマホ対応は P2
- 時間経過による回復・減少、行動のクールダウンなどの行動制限はなし
- パワー・コンディションは休息アクションで回復する
- データは行動ごとに自動保存する（手動の「データ保存」はない）
- 「空腹度」は「満腹度」と表記する（DB 列・コード上の名前も `fullness`）
- 休息は満腹度 -5、コンディション +30（BMI 補正・満腹度ペナルティなし）
- 食事・回復アイテム・食堂メニューを含め、すべてのアイテムに能力上昇の効果がある
- 体重は 0.1kg 単位で扱う（DB・サーバー内部はグラムの整数 `weight_g`、マスタ・画面は kg）
- 仕事をすると職業ごとに決まった量だけ体重が減る
- 体重の増減は食事・ジム・仕事とも 0.1kg 単位で調整する（例: パン +0.8kg、ステーキ +3.0kg、ジム -0.8kg）
- アイテムの種類は目安で、パワー回復などの効果はどの種類にも付けられる。満腹度の回復は食事のみ
- 食事でもコンディションが変化する（上がる・変わらない・下がるものがある）
- 炊き出しには能力上昇などの効果を付けない
- マップは 32×32 のドット絵アイコンで表示する（1マス 32px）。`assets/icons/` の画像で差し替えられる
- 施設ごとに店主のアイコンとセリフを表示する（炊き出しおじさんを含む）
- ジムは種目、学校は授業ごとに選ぶ（上がる能力・体重の変化は種目・授業ごとに定義）
- 居酒屋を追加。お酒は満腹でも飲めるが、コンディションが下がり体重が増える
- 銀行を追加。預金はストリートファイトで負けても減らず、総資産に含める。預金があると炊き出しは利用できない
- 闇市場を追加。身長（120〜220cm）・体重（30〜200kg）を大きく変える薬や、高価な能力アップ品を扱う。副作用は決まった内容で、効果は表示する
- 職業に系統と上位職を追加。昇進条件は昇進元の職業レベル・総資産（＋能力値）。昇進は手動、経験値は職業ごとに残す
- スポーツ選手はフィットネストレーナーに名称変更（上位職: パーソナルトレーナー → ジムオーナー）
- 力士・総合格闘家・カレー屋・バーテンダーの系統を追加。力士は体重（80 / 100 / 120kg 以上）が条件で、体重が下回っても降格しない。カレー屋は理科と語学が条件
- 会社員系統（会社員 → 係長 → 課長 → 部長 → 社長）は削除。削除した職業に就いていた住民は起動時に無職に戻す
- 持ち金がちょうど 0円 のときだけ食堂で無料の炊き出しを利用できる（小銭が残ったら丁半で賭けて0円にするか勝つかの一か八か）

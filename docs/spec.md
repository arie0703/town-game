# TOWNゲーム 要件定義書（spec）

---

## 1. 概要

ブラウザで遊べるTOWNゲーム（バーチャル世界での生活シミュレーション）を作る。
プレイヤーは町の住民として登録し、仕事でお金を稼ぎ、学校・ジムで能力を鍛え、アイテムを集め、他の住民と戦ったり恋人・配偶者になったりする。

### 1.1 方針

- 実装はシンプル・最小限とする。実装が重い要件は「後回し（Phase 2 以降）」として本書に残し、後から追加する。
- 要件には優先度を付ける。
  - **MVP**: 最初のリリースに必須
  - **P2**: MVP後に追加する候補
  - **P3**: 余裕があれば検討する

---

## 2. 技術構成

- フロントエンド: HTML / CSS / TypeScript の SPA（フレームワークなし、ビルドは Vite、hash ルーティング）
- バックエンド: TypeScript（Node.js + Hono）
- DB:
  - ローカル開発: SQLite（ファイル1つで完結させる）
  - 公開サーバー: Supabase の PostgreSQL
- DBアクセス: Kysely（SQLite / PostgreSQL の両方に対応するクエリビルダー）
  - MVP は SQLite のみ対応。PostgreSQL 対応（環境変数での接続先切り替え）はデプロイ時（P2）に追加する
  - 後で PostgreSQL に移せるよう、方言依存の機能（SQLite 固有の挙動等）は使わない
  - マイグレーションの仕組みは作らず、起動時に `CREATE TABLE IF NOT EXISTS` でテーブルを作成する
- マスタデータ（職業・アイテム・メニュー・マップ）: TypeScript の定数ファイルで持ち、DB には入れない
- 通信: JSON REST API
- 認証: Hono の署名付き Cookie にユーザー ID を保存する（セッションテーブルは作らない）。パスワードはハッシュ化（bcrypt 等）して保存する
  - Supabase Auth は使わない（ローカル SQLite 環境と認証方式を揃えるため）。P2 以降で移行を検討してもよい

> 補足: ログイン・他ユーザーとのストリートファイト・恋人/配偶者など「他ユーザーとの関わり」があるため、localStorage だけでは成立しない。最小構成としてサーバー + DB を採用する。
> ゲームロジック（勝敗判定・給料計算など）は不正防止のため必ずサーバー側で計算する。

### 2.1 環境

- **ローカル開発**（MVP）: `npm run dev` でフロント（Vite）・サーバー（Hono）を起動。DB は SQLite
- **公開サーバー**（P2）: AWS Fargate（ECS）でサーバーを動かす想定 + Supabase PostgreSQL
  - アプリはコンテナ（Dockerfile）で動かす。Hono が API とビルド済み SPA の静的配信を両方担う
  - 接続情報（DB URL・セッション秘密鍵）は環境変数で渡し、リポジトリにコミットしない

## 3. 用語

- **住民（ユーザー）**: ゲームに登録したプレイヤー
- **能力**: 頭脳・身体・その他の各パラメータ（鍛えると上がる、恒久的な値）
- **パワー**: 行動に消費する値（身体パワー・頭脳パワー）。休息・回復アイテムで回復する
- **コンディション**: 体調。行動結果（給料・勝率・トレーニング効果）に影響する

---

## 4. 機能要件

### 4.1 アカウント（MVP）

- 住民登録ができる（ユーザー名・パスワード）
  - ユーザー名は一意。文字数制限（例: 2〜12文字）
  - パスワードは8文字以上
- 登録時に初期パラメータを付与する
  - 能力: 全項目 20
  - 身長: 150〜200cm のランダム（整数）
  - 体重: 45〜90kg のランダム（整数）
  - 職業: 無職
  - 所持金: 10,000円（仮）
  - 身体パワー・頭脳パワー: 最大値
  - コンディション: 100、空腹度: 50（仮）
  - 恋人・配偶者: なし
- ログイン / ログアウトができる
- ログイン状態はセッションで保持する
- （P2）パスワード変更
- （P3）退会（データ削除）

### 4.2 能力（MVP）

各能力は 0 以上の整数。**上限なし**（後で上限を追加する可能性あり → 上限値を1箇所の定数で管理できる作りにしておく）。

- **頭脳**: 国語 / 数学 / 理科 / 社会 / 語学 / 音楽 / 美術
- **身体**: ルックス / 体力 / 健康 / スピード / パワー / 腕力 / 脚力
- **その他**: LOVE / 面白さ

派生値:

- **頭脳合計**: 頭脳カテゴリの合計（就職条件・頭脳パワー最大値に使用）
- **身体合計**: 身体カテゴリの合計（就職条件・身体パワー最大値・ストリートファイトに使用）

### 4.3 ステータス（MVP）

- **持ち金**: 現金
- **総資産**: 持ち金 + 所有土地の評価額（+ P2で預金）
- **職業**: 現在の職業（初期値: 無職）
- **身体パワー**: 現在値 / 最大値。仕事・ジム・ストリートファイトで消費。最大値は身体合計から算出
- **頭脳パワー**: 現在値 / 最大値。仕事・学校で消費。最大値は頭脳合計から算出
- **コンディション**: 0〜100。仕事・敗北・空腹で低下、休息・アイテムで回復
- **身長**（cm）
- **体重**（kg）: 食事で増加、トレーニングで減少
- **BMI**: 体重(kg) ÷ 身長(m)² で自動計算（表示のみ・保存しない）
- **空腹度**: 0〜100（100 = 満腹MAX）。仕事・ジム・ストリートファイト・休息などの行動で減少、食事アイテムで回復
- **恋人**: 恋人のユーザー（0〜1人）
- **配偶者**: 配偶者のユーザー（0〜1人）

コンディションの補正（例）:

- 空腹度が一定以下（例: 20未満）のとき、行動するたびにコンディションが低下する
- BMI が標準範囲（18.5〜25）から外れるとコンディション回復量が減る

### 4.4 マップ（MVP）

- 15×15 のマス目で町を表示する
- 各マスは「施設」「空き地」「道（何もない）」のいずれか
- 施設のマスをクリックすると施設画面に入る（キャラクターの移動・移動時間は設けない）
- 施設配置は固定（マスタデータで定義）

施設一覧:

- **お店**（MVP）: アイテム購入
- **職業安定所**（MVP）: 職業の確認・転職
- **学校**（MVP）: 頭脳能力を上げる
- **トレーニングジム**（MVP）: 身体能力を上げる
- **ギャンブル施設**（MVP）: お金を賭ける
- **不動産屋**（MVP）: 空き地の購入
- **空き地**（MVP）: 不動産屋で購入可能な土地。購入済みなら所有者名を表示
- **食堂**（MVP）: その場で食事をする
- **役場**（MVP・追加提案）: 住民一覧（総資産ランキング順）の閲覧
- **病院**（P2）: お金を払ってコンディションを全回復
- **銀行**（P2）: 預金・引き出し・送金

### 4.5 アクション: 仕事（MVP）

- 職業に就いた状態で「仕事」をすると給料が得られる
- 職業ごとに以下を定義する（マスタデータ）
  - 基本給
  - 就職条件（例: 頭脳合計 ≥ N、身体合計 ≥ N、特定能力 ≥ N）
  - 消費パワー（身体パワー / 頭脳パワーのどちらを何ポイント）
  - コンディション低下量
  - 仕事で上がる能力（例: プログラマーは数学 +1）
- 給料 = 基本給 × コンディション補正（例: コンディション50未満で減額）
- パワーが足りない場合は仕事できない
- 職業の例:
  - 無職（仕事不可）
  - アルバイト（条件なし・低賃金）
  - 会社員（頭脳合計が一定以上）
  - 教師（国語・社会が一定以上）
  - プログラマー（数学が一定以上）
  - スポーツ選手（身体合計が一定以上）
  - モデル（ルックスが一定以上、BMIが範囲内）
  - 芸人（面白さが一定以上）
- （P2）職業経験値・職業レベル（勤務回数で昇給・上位職解放）

### 4.6 アクション: 休息（MVP）

- ホーム画面から「休息」を実行すると、身体パワー・頭脳パワー・コンディションが一定量回復する
- 無料で実行できる（お金がなくても詰まないようにするため）
- 休息すると空腹度が減る（休息を繰り返すには食事が必要＝お金がかかる、という循環を作る）
- 空腹度が 0 のときは休息できない
- 回復量は定数で管理し、調整できるようにする

### 4.7 アクション: 職業安定所（MVP）

- 職業一覧と就職条件・給料を表示する
- 条件を満たす職業に転職できる
- 退職（無職に戻る）ができる

### 4.8 アクション: ストリートファイト（MVP）

- 「戦う」を押すと、自分以外の住民からランダムに対戦相手が選ばれる（相手はオンラインでなくてもよい。相手の操作は不要）
  - 相手を指名することはできない
- 身体パワーを消費する
- 勝率は身体能力（身体合計 + パワー・スピード等の重み付け）の比で決める
  - 例: 勝率 = 自分の戦闘力 ÷ (自分の戦闘力 + 相手の戦闘力)、コンディションで補正
  - 下限・上限を設ける（例: 5%〜95%）＝弱くても勝てる可能性を残す
- 勝敗の影響を受けるのは **挑戦した側のみ**
  - 勝利: 町から賞金を得る（金額は仮: 相手の戦闘力に応じて増える）
  - 敗北: **持ち金が半分になる**（端数切り捨て、失ったお金は消滅）。加えてコンディションが大きく低下する
- 挑戦された側には一切影響しない（お金・コンディション・パワーなどすべて変化なし）
- 戦闘結果は挑戦した側の出来事ログにのみ記録する（挑戦された側には履歴も残らない）
- （P2）勝敗数・ファイトランキング

### 4.9 アクション: アイテム（MVP）

- お店でアイテムを購入できる（所持金から差し引く）
- 所持アイテムを一覧表示し、使用できる
- アイテム種別:
  - **食事アイテム**: 空腹度を回復、体重が増える。**空腹度がMAXのときは使用不可**
  - **能力アップアイテム**: 特定能力を上げる（例: 参考書 → 数学 +3）
  - **回復アイテム**: コンディション・パワーを回復（例: 栄養ドリンク）
- 使用すると所持数が減る（消耗品）
- （P2）アイテム売却（リサイクルショップ）
- （P2）他ユーザーへのアイテムプレゼント
- （P3）コレクション用アイテム（使用不可・図鑑表示）

### 4.10 アクション: 学校（MVP）

- 頭脳能力の科目を選んで勉強する
- 頭脳パワーと授業料を消費し、選んだ科目が上がる
- 上昇量はコンディションで補正

### 4.11 アクション: トレーニングジム（MVP）

- 身体能力の項目を選んでトレーニングする
- 身体パワーと利用料を消費し、選んだ項目が上がる
- 体重が少し減る、空腹度が減る

### 4.12 アクション: 食堂（MVP）

- メニュー（マスタデータ）から選んで、その場で食事をする（お金を払う）
- 空腹度が回復し、体重が増える（メニューごとに回復量・増加量・価格を定義）
- **空腹度がMAXのときは食事できない**
- お店の食事アイテムとの違い: 食堂は持ち歩けない代わりに、同じ回復量なら食事アイテムより安い
- **炊き出し**: 持ち金が **ちょうど 0円** のときだけ、無料の食事（おにぎり1個）をもらえる
  - 空腹度が少し回復する（回復量は通常メニューより少ない。仮: +30）
  - 空腹度が 0 で休息もできず、お金もない状態で詰まないための救済措置
  - 1円でも持っていると利用できない（あえて厳しくしている）。小銭が残って何も買えないときは「丁半で最後の小銭を賭けて、勝てば食堂、負ければ炊き出し」という一か八かの選択をさせる
  - 持ち金が最安メニュー未満かつ 1円以上のとき、食堂画面に「炊き出しは一文無しの方限定です」と表示し、ギャンブル施設へ誘導する
  - 炊き出しを利用すると出来事ログに「炊き出しの列に並んだ」と記録し、利用回数を累計する

### 4.13 アクション: ギャンブル（MVP）

- **丁半** のみ実装する
  - 賭け金を入力し「丁（偶数）」か「半（奇数）」を選ぶ
  - サイコロ2個の合計で判定（サーバー側で乱数生成）
  - 当たり: 賭け金の2倍を受け取る / 外れ: 賭け金を失う
- 賭け金は 1円以上・所持金以下（1回の上限は仮で10万円）
- 「全額賭ける」ボタンを用意する（所持金が上限以下のときのみ）
- （P3）丁半以外のギャンブル（スロット・競馬・カードゲーム等）

### 4.14 不動産（MVP・簡易版）

- 不動産屋で空き地を購入できる（土地ごとに価格を設定）
- 購入した土地はマップ上に所有者が表示される
- 所有土地は総資産に計上される
- 売却はできない（購入のみ）
- （P2）土地に家を建てる（家の種類で価格・評価額が変わる）
- （P3）家の外観・自宅ページのカスタマイズ

### 4.15 恋愛・結婚（MVP・簡易版）

ステータスに恋人・配偶者があるため、最小限の申請/承認フローのみ実装する。

- 他の住民に「交際申請」を送れる → 相手が承認すると恋人になる
- 恋人に「プロポーズ」できる → 相手が承認すると配偶者になる（恋人欄は空になる）
- 別れる / 離婚できる（一方的に可）
- 恋人・配偶者がいる人には交際申請できない
- 申請の成功判定に LOVE・ルックスを使うかは要検討（MVPでは相手の承認のみ）
- （P2）デート（お金を払って LOVE が上がる等）
- （P3）子供・子育て、同居人

### 4.16 住民一覧（MVP・追加提案）

- 役場で住民一覧を表示する。一覧は総資産の多い順に並べ、総資産ランキングを兼ねる
- 表示項目: 順位・名前・職業・総資産・恋人/配偶者
- 個別のプロフィール画面は作らない
- （P2）能力別ランキング・ファイト勝利数ランキング・カップルランキング・炊き出し常連ランキング（炊き出し利用回数）

### 4.17 ホーム画面（MVP）

- 自分のステータス・能力を一覧表示する
- 主要アクション（仕事・休息・アイテム・ストリートファイト）へのボタン
- マップを表示する
- 直近の出来事ログ（給料を得た、勝った・負けた、交際申請が来た 等）を表示する

### 4.18 コミュニケーション（P2）

- 町の掲示板（全体チャット / 挨拶）
- 住民間メール（ダイレクトメッセージ）
- NGワード・投稿の削除（自分の投稿のみ）

### 4.19 その他の候補（P3）

- 株式（価格が変動、売買）
- オークション（住民間のアイテム売買）
- ランダムイベント（再読み込み時に一定確率でお金を拾う等）
- 病気（健康が低いと病気になり、病院で治療）
- 管理画面（ユーザーBAN、マスタデータ編集）
- 町ポイント・ログインボーナス

## 5. 非機能要件

### 5.1 セキュリティ（MVP）

- パスワードはハッシュ化して保存する（平文保存禁止）
- 認証Cookieは署名付きとし、HttpOnly / SameSite=Lax を付与する
- 状態を変更する API は POST で受け、CSRF 対策を行う（Hono の `csrf` ミドルウェア）
- ゲームの計算（給料・勝敗・ギャンブル結果）はすべてサーバー側で行い、クライアントの値を信用しない
- ユーザー入力（名前・掲示板等）は出力時にエスケープする（XSS対策）
- ログイン試行回数の制限（P2）

### 5.2 整合性（MVP）

- お金・アイテムの増減はトランザクション内で行う（二重送信で二重に給料が入らないようにする）

### 5.3 UI / 動作環境（MVP）

- PC ブラウザ（Chrome / Edge / Firefox / Safari の最新版）で動作する
- スマホ対応は MVP では行わない（P2）
- 画面はシンプルなレトロ風デザイン（テーブル・枠線中心）で可

### 5.4 開発・運用

- （MVP）ローカルで `npm run dev` 一発で起動できる
- （MVP）テストコードは実装しない（動作確認は手動）
- （MVP）Lint / Formatter は導入しない（`tsc` の型チェックのみ）
- （MVP）1パッケージ構成とする（npm workspaces は使わない）
- （MVP）数値（給料・価格・回復量・初期値など）はマスタデータ / 定数ファイルにまとめ、ロジックを触らずに調整できる
- （P2）PostgreSQL 対応（環境変数 `DATABASE_URL` で接続先を切り替え）
- （P2）公開サーバー（AWS Fargate 想定）へのデプロイ（Supabase PostgreSQL に接続）
- （P2）Supabase 側のバックアップ設定、本番用 Cookie 署名鍵の管理

## 6. データモデル（概略）

MVP で必要な主なテーブル:

- `users`: id, name, password_hash, money, soup_kitchen_count, job_id, body_power, brain_power, condition, height, weight, hunger, lover_id, spouse_id, created_at
- `abilities`: user_id, 各能力値
- `user_items`: user_id, item_id, quantity
- `lands`: cell_id, owner_id, purchased_price
- `relationship_requests`: id, from_id, to_id, type(交際/プロポーズ), status
- `events`: id, user_id, message, created_at（出来事ログ。ストリートファイトの結果もここに記録する）

マスタデータ（DB に入れず、TypeScript の定数ファイルで持つ）:

- 職業: id, name, base_salary, requirements, power_type, power_cost, condition_cost, ability_gain
- アイテム: id, name, type, price, effect
- メニュー: id, name, price, hunger_recovery, weight_gain
- マップ: 15×15 の各マスの type（施設 / 空き地 / 道）, facility_id, land_price

## 7. 画面一覧（MVP）

1. トップ（ログイン / 住民登録）
2. ホーム（ステータス・マップ・出来事ログ）
3. 施設画面（お店 / 職業安定所 / 学校 / ジム / 食堂 / ギャンブル / 不動産屋 / 役場＝住民一覧）

## 8. 未決事項（要確認）

### 8.1 決定済み

- ローカルは SQLite、公開時は Supabase PostgreSQL
- 初期値は能力 ALL 20、身長 150〜200cm / 体重 45〜90kg のランダム、職業は無職
- ギャンブルは丁半のみ
- ストリートファイトは挑戦した側のみ勝敗の影響を受ける。敗北時は持ち金が半分、挑戦された側は影響なし
- 能力値の上限なし（後で追加する可能性あり）
- バックエンドは Hono
- テストコードは実装しない
- フロントエンドは SPA（hash ルーティング）、1パッケージ構成
- MVP は SQLite のみ対応、PostgreSQL 対応はデプロイ時
- ストリートファイトの相手はランダムのみ。挑戦された側の履歴は残さない
- 不動産は購入のみ
- 住民一覧は総資産ランキングを兼ねる（プロフィール画面なし）
- 総資産は持ち金 + 土地
- スマホ対応は P2
- 時間経過による回復・減少、行動のクールダウンなどの行動制限はなし
- パワー・コンディションは休息アクションで回復する
- データは行動ごとに自動保存する（手動の「データ保存」はない）
- 持ち金がちょうど 0円 のときだけ食堂で無料の炊き出しを利用できる（小銭が残ったら丁半で賭けて0円にするか勝つかの一か八か）
